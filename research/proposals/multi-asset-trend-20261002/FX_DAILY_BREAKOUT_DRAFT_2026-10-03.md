## 今回進めたことと判断

数量の最小単位と費用を含む計算例を実装し、8つの合成テストがPASSした。市場履歴、実口座、既存HR/CSM入力・結果にはアクセスしていない。

## 固定候補：売買の定義

以下は採否をレビューできる具体案。数値は最適化しておらず、優位性を示す根拠もまだない。

| 項目 | 草案 |
|---|---|
| 対象 | USD/JPYのみ。買い・売りを対称に扱う |
| 日足 | ニューヨーク17:00区切り。America/New_Yorkの夏時間を反映。休日を空足や前値で埋めない |
| 信号価格 | 同一ソースのBid OHLC。Ask/スプレッドは執行評価用に別保持。Mid系列への黙った置換禁止 |
| 買い | 最新の確定日足終値が、その日を除く直前20日足の最高高値を厳密に上回る |
| 売り | 最新の確定日足終値が、その日を除く直前20日足の最安安値を厳密に下回る |
| 同値 | 信号なし |
| 確認時刻 | 平日20:00 JST。直近の確定日足が当日取得済みであることを確認 |
| 執行候補 | 信号を確認後の20:00〜20:05 JSTの最初の利用可能Bid/Ask。遅れたらその機会は見送り |
| 初期損切り | 実約定価格から2×ATR(14)。買いは下、売りは上。広げない |
| 利食い | 固定利食い・追随ストップなし |
| 通常の決済 | 反対信号で20:00の確認後に決済。即時反転はせず、その確認回は新規注文しない |
| 時間決済 | 約定後10番目の平日20:00確認で決済。約定当日の確認を0番目とする |
| 週末 | 金曜は新規なし、既存ポジションは金曜23:00 JSTに決済 |
| 再入場 | 決済した確認回では新規なし。その後の確認で同じ条件を満たした場合のみ候補 |
| 同時保有 | 各口座1つ。同方向の両社合計予定損失50円以内 |

ATRは値動きの大きさを表す指標。TR=max(高値−安値, abs(高値−前日終値), abs(安値−前日終値))。最初の14TRの平均で初期化し、以降は(前ATR×13+当日TR)/14で更新するWilder方式を候補とする。初期化開始日を固定する必要がある。ATR算出と20日高安の両方が揃うまで信号なし。
同時刻に複数の決済条件が成立した場合は、すでに約定した損切り、時刻の早い決済要求の順に一度だけ処理する。欠測時の取引・決済の扱いはまだ実装していない。

注文数量に合わせて損切りを縮めない。ボーナスで数量を増やさない。両建て・ナンピン・マーチンゲールは採用しない案。チャートを見て任意に条件を変更しない。
この草案を実行可能にするには、本人が20:00/23:00に対応できるか、注文と決済の機能、未配信・休場・障害時の処理を確認する必要がある。実売買準備完了ではない。

## 損失・数量・レバレッジの草案

- 1口座1回の予定損失予算は50円。同方向で両口座を使う場合は各25円以下に割り当て、合計50円以内。最小数量を満たせなければ片方または両方を見送る。
- 各口座の週初資産から入出金を除いた減少が150円に達したら新規停止。含み損込みの自己資金が9,500円以下なら実売買を停止する案。決済・停止時の滑りで超える可能性は残る。
- 実効レバレッジ（円換算ポジション額÷自己資金）を2倍以下とする初期案。ブローカーの設定上限とは別。証拠金余裕とロスカット条件の確認を代替しない。
- スワップ支払い、滑り、手数料の余裕を含めて数量を切り下げる。将来の損失を保証する式ではない。

実価格を使う場合は、買い=Askで入りBidで出る、売り=Bidで入りAskで出る。損切りもそれぞれの決済側価格で評価する。約定価格から損切り価格までの距離にスプレッドが反映されている場合、同じスプレッドを別に加算しない。

## オフラインで計算した数量例

下の数字は相場・費用の観測値ではない。仮の価格150円/ドル、自己資金1万円、実効レバレッジ上限2倍、固定費0円、Mid価格の損切り距離に対する1通貨あたり費用余裕0.02円とした算術例。実売買の損切り定義とは区別する。

| Mid価格の距離 | 予算 | 松井の算術上の数量 | XMの算術上の数量 |
|---|---:|---:|---|
| 0.30円 | 50円 | 133通貨 | 130通貨=0.13 Micro lot |
| 0.50円 | 50円 | 96通貨 | 見送り |
| 1.00円 | 50円 | 49通貨 | 見送り |
| 0.30円 | 25円 | 78通貨 | 見送り |

0.30円・50円予算の例は損失予算より実効レバレッジ上限が数量を制限する。両社に25円ずつ割り当てる例では、XMの最小数量を満たせない。この制約を利益率や勝率と取り違えない。

## 検証の順序と採否

1. 元データの受入: ソース・利用権、日時と夏時間、Bid/Ask、実際の取引可能日、公開/取得時刻、スワップ、数量・証拠金条件を確認する。価格だけの履歴から費用後利益を認定しない。
2. データ期間・初期化・比較を結果前に固定。候補比較は現金、同じ資金/実効レバレッジ上限のドル円買い保有。トレンドの利益と単なるドル保有の利益を区別する。買い保有との事前リスク差を評価し、結果後の実現ボラティリティで帳尻を合わせない。
3. 時点、当日除外、売買方向、費用、週末・時間決済、同一バー内の約定順を合成ケースで検査する。日足だけでストップ約定を精密再現できるとは扱わない。
4. 固定した過去再現を一度行い、費用後損益、最大資産減少、平均損益、売買回数、保有時間、費用の内訳、期間別寄与、数量不足での見送り率を両社別に出す。
5. 数値の採用閾値と評価期間は人間判断待ち。費用後損失・データ/時点不備・数量がほぼ成立しない場合はHOLD/REJECT候補。数値が未固定のまま市場結果を見て合格条件を決めない。
6. 将来の模擬観測は固定ルールの執行確認。3か月は見直し時期で、有効性が証明される期間ではない。毎月一定利益をノルマにしない。実資金での試行は別の採用判断。
